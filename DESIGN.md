# Design

## Структуры данных и алгоритмы

- `GameState` — типизированный объект состояния игры, `history` — массив объектов `Attempt` с комбинацией и результатами `bulls`/`cows`. Массив сохраняет порядок попыток; цифры хранятся как символы, чтобы поддерживать ведущие нули и hex. Типы описаны в `types.ts`.
- `Set` обеспечивает уникальность цифр в `generateSecret` и `isValidGuess`. `createStore` хранит актуальное состояние и уведомляет подписчиков об изменениях.
- `evaluateGuess` считает `bulls` по совпадениям на тех же позициях. `cows` — цифры, которые есть в обеих комбинациях, но стоят не на своих позициях; уже учтённые цифры пропускаются.
- `countPossibleSecrets` использует формулу `P(length, base) = base × P(length - 1, base - 1)` и кэширует результаты в `Map`.

## Сложность

Пусть `n` — длина комбинации, `b` — основание. Операции `Set` и `Map` считаются `O(1)` в среднем.

| Функция                | Время                                         | Память     | Обоснование                                                                                                   |
| ---------------------- | --------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------- |
| `generateSecret`       | Ожидаемо `O(b log b)`                         | `O(n)`     | Случайные цифры выбираются до получения `n` уникальных; по мере заполнения набора повторов становится больше. |
| `evaluateGuess`        | `O(n²)`                                       | `O(n)`     | Для каждой цифры выполняются линейные поиски в массивах, включая проверку уже учтённых символов.              |
| `isValidGuess`         | `O(n × b)`                                    | `O(n + b)` | Проверяются уникальность и допустимость каждой цифры; проверка символа ищет его в алфавите длины до `b`.      |
| `countPossibleSecrets` | `O(n)` при промахе кэша, `O(1)` при попадании | `O(n)`     | Рекурсия уменьшается на единицу за вызов и сохраняет промежуточные значения в кэше.                           |

## Принципы Clean Code

- **Разделение ответственности:** `createDigitValidator` проверяет одну цифру, `isValidGuess` — всю попытку, `evaluateGuess` вычисляет результат.
- **Переиспользование:** `isValidGuess` и обработчики ввода используют `createDigitValidator`.
- **Разделение логики и интерфейса:** функции в `core/` не зависят от DOM, а `renderGame` отвечает за игровой интерфейс.
- **Иммутабельность:** `createStore` принимает функцию обновления; экраны настроек и игры создают новые объекты состояния.
- **Тестируемость:** `generateSecret` принимает источник случайных чисел параметром; функции из `core/` покрыты отдельными тестами.
